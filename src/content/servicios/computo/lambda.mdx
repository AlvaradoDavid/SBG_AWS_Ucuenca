## Descripción

AWS Lambda es cómputo *serverless*: subes tu código (una función) y AWS se encarga de todo lo
demás — aprovisionar el servidor, escalarlo y apagarlo cuando no se usa. No hay una máquina que tú
administres; solo pagas por el número de invocaciones y el tiempo que tarda cada una en ejecutarse,
medido en milisegundos.

Es el opuesto conceptual de EC2: en vez de "una computadora siempre encendida", es "código que
aparece, corre y desaparece" cada vez que algo lo dispara.

## Cómo funciona

1. Defines una **función** con tu código y eliges cuánta memoria darle.
2. Conectas un **trigger**: una petición de API Gateway, un objeto nuevo en S3, un horario.
3. Cuando el trigger ocurre, AWS levanta un entorno, ejecuta tu código y lo destruye.
4. Si llegan mil eventos simultáneos, AWS levanta mil ejecuciones en paralelo sin que tú configures nada.

## Manos a la obra

- Crea una función en Python desde la consola con el runtime por defecto.
- Configura un trigger de S3 sobre un bucket de prueba, evento "objeto creado".
- Haz que la función escriba en los logs el nombre del archivo que la disparó.
- Sube un archivo cualquiera al bucket y revisa CloudWatch Logs: ahí está tu evento.
