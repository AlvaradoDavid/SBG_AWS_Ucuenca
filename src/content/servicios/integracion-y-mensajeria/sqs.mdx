## Descripción

Una cola parece una pieza modesta y es una de las decisiones de arquitectura con mayor efecto. Sin
ella, si el sistema que procesa se cae o se satura, las peticiones se pierden y quien las envió se
queda esperando. Con ella, el trabajo se acumula y se procesa cuando hay capacidad.

SQS aporta además dos garantías que a mano cuestan mucho: un mensaje tomado por un consumidor queda
**invisible** para los demás mientras se procesa, y si el proceso falla, el mensaje **reaparece** para
que otro lo intente. Nada se pierde en silencio.

## Cómo funciona

1. Creas una cola, **estándar** si el orden no importa o **FIFO** si sí.
2. El productor envía mensajes con `SendMessage` y sigue con lo suyo.
3. El consumidor pide mensajes; los que recibe quedan ocultos durante el **tiempo de visibilidad**.
4. Al terminar, el consumidor **borra** el mensaje. Si no lo borra, el mensaje reaparece y se reintenta.
5. Tras varios intentos fallidos, el mensaje pasa a la **cola de mensajes fallidos** para revisarlo.

## Manos a la obra

- Crea una cola estándar y envía tres mensajes desde la consola.
- Recíbelos con la CLI **sin borrarlos** y observa cómo reaparecen pasado el tiempo de visibilidad.
- Conecta una función Lambda como consumidor de la cola y comprueba que se invoca sola.
- Configura una cola de mensajes fallidos con un máximo de tres intentos y provoca un fallo a propósito.
- Activa el sondeo largo y compara el número de peticiones en las métricas de CloudWatch.
